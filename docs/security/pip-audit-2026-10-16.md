# pip-audit — 16 October 2026

Tool: pip-audit 2.10.1.

## Project resolve

Command: `pip-audit --progress-spinner off .` (builds an isolated environment from this repository).

Before the `mcp` floor change, a project resolve already selected mcp 1.30.0 and reported no known vulnerabilities. The same command after `mcp>=1.30,<2` reported the same result:

```
No known vulnerabilities found
```

`pip-audit -r pyproject.toml` is not valid. pip-audit treats `-r` as a requirements file, and `pyproject.toml` is not one.

## Ambient developer environment (not this project)

`pip-audit` with no path audited the machine environment. That environment contains OS and unrelated packages (ansible, pip, setuptools, urllib3, jinja2, httplib2, oauthlib, wheel) plus mcp 1.29.0. Those packages are not dependencies of wallet-mcp. The one row that mattered for the old dependency range is mcp 1.29.0 / CVE-2026-59951, fixed in 1.30.0 and 2.2.0. The CVE is an unbounded session leak in stateful Streamable HTTP. This server uses stdio. The floor was raised anyway so a future HTTP transport cannot install the vulnerable release.

`btc-wallet-mcp` itself is skipped because it is not published on PyPI.
